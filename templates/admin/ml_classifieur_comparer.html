{# ========== EXPLICATION SCIENTIFIQUE ========== #} {% if resultats.baseline_gagne_sur_ml %}
Pourquoi la baseline bat le ML ?

C'est un resultat scientifiquement interessant qui s'explique par 3 facteurs :

  1. Dataset trop petit ({{ resultats.dataset_size }} exemples) : avec 100 exemples d'entrainement et 7 categories, cela fait seulement ~14 exemples par classe en moyenne. Un modele ML a besoin de beaucoup plus pour generaliser.
  2. Probleme tres explicite : les noms de produits contiennent presque toujours le mot-cle de leur categorie (« tomate », « yaourt », « pain »). Une simple regle suffit.
  3. TF-IDF perd de l'information : avec si peu de donnees, la vectorisation TF-IDF ne peut pas capturer les nuances fines du vocabulaire alimentaire.

Conclusion : sur ce probleme et ce volume de donnees, l'approche par regles reste competitive. L'approche hybride (regles + ML) est la vraie solution d'ingenierie : elle beneficie de la precision des regles sur les cas connus et de la couverture du modele ML sur les cas inconnus.

{% endif %} {# ========== PERSPECTIVES ========== #}
Perspectives d'amelioration
  • Augmenter le dataset : passer de {{ resultats.dataset_size }} a 400-500 exemples. A ce seuil, les modeles ML devraient surclasser la baseline (le vocabulaire devient trop varie pour les regles).
  • Ajouter des langues locales : arabe tchadien, ewondo, duala, etc. Les regles sont monolingues, le ML peut apprendre plusieurs langues.
  • Mecanisme d'apprentissage continu : chaque annonce validee par l'admin devient un nouvel exemple d'entrainement. Le modele s'ameliore avec le temps.
  • Embeddings semantiques : utiliser fastText ou Word2Vec pour capturer les similarites entre produits (ex: « tomate » et « tomates » sont proches).
